# Instalação — TAJO TAP V4.1

**Sistema desenvolvido por João Paulo Brandão.**

## 1. Supabase — primeiro

Se as migrations 001, 002 e 003 já foram executadas, **não execute novamente**.

No SQL Editor, execute somente:

`supabase/migrations/004_activation_v4_and_batches.sql`

Ao final, a consulta da própria migration deve mostrar:

- `tap_validate_activation_pin_v4(text,text)`;
- `tap_activate_plate_v4(text,text,uuid,text,text,text,text,text,text,text)`;
- `tap_plate_batches`.

Opcionalmente rode `supabase/VERIFY_V4_1.sql`.

## 2. GitHub

Substitua o conteúdo do repositório atual pela V4.1. É importante registrar também os arquivos apagados de versões antigas:

```bash
git add -A
git commit -m "TAJO TAP V4.1 - ativacao e producao em lote"
git push origin main
```

A pasta `/api` deve continuar com **somente** `index.js`. Os módulos internos ficam em `/server`.

## 3. Vercel

Use o mesmo projeto ligado a `go.tajodigital.com.br` e mantenha as variáveis:

- `SUPABASE_URL`
- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SECRET_KEY`
- `PANEL_BASE_URL=https://go.tajodigital.com.br`

Depois do deploy, teste `/api/health`.

## 4. Teste da ativação existente

Abra novamente `/atv/TT-LFBTXK`.

- Se a unidade ainda estiver pendente, conclua com o PIN original.
- Se uma tentativa anterior já tiver gravado a ativação, a tela informará que a unidade já está ativa.
- Depois teste `/q/TT-LFBTXK`: ele deve redirecionar para o destino salvo.

## 5. Teste de lote

No Super Admin:

`Produção → Novo lote → escolha quantidade → Gerar lote`

Baixe imediatamente o **Mapa interno CSV**, porque os PINs em texto puro não podem ser recuperados depois. Para a gráfica, use **Imprimir / Salvar PDF** ou o **Arquivo vetorial HTML**.
